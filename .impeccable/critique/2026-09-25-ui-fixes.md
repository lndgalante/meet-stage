# BetterMeets UI/UX fixes

Implemented the actionable recommendations from the September 25 review, preserving the native macOS visual system.

| Review finding | Implemented behavior |
| --- | --- |
| Audience visibility | Labeled Stage Only action, complete setup sequence, in-app guide, controls-visible guidance, and local “On stage” status. |
| Capture controls | Source status, Pause/Resume, and Clear Stage share the footer. Repeat source selection keeps capture live. The floating source tools include transport and Show Controls. |
| Settings focus | All settings entry points open one native window. Tool settings do not focus the source app. Navigation and window size remain stable across panes. |
| Source browsing | Resizable sidebar, saved width, automatic compact rows in short windows, always-open tools, system scroll indicators, deduplicated app/title labels, stronger identity text, and quieter shortcuts. |
| Window identification | Enlarged previews show full distinguishing titles. Keyboard focus uses a visible outline and immediate minimal scrolling. |
| Recovery | Specific permission and failure content, adjacent retry/choose actions, contextual restart guidance, local Unpin for unavailable pins, and no diagnostic errors in audience placeholders. Automatic discovery preserves capture failures until an explicit recovery action. |
| Tool discoverability | Always-open tools share one settings gear. Consistent feature names across tools, menus, settings, and help. Enabled effects waiting for a source have a shared readiness hint. |
| Effect preview clarity | Every effect pane displays its master On/Off switch beside the preview. |
| Visual details | Coordinated paused tint and symbol, live dot, one outer source outline, transparent unstyled capture backdrop, consistent inset source corners, and removal of the redundant inner stage clip. Existing press feedback and restrained hover motion remain. |
| Design documentation | README, PRODUCT, DESIGN, and the Impeccable sidecar now describe the current native workspace and controls. |

Validation: development app builds and signs successfully; all 123 Swift tests pass. Regression coverage includes repeat selection, unavailable-pin removal and persistence, and native sidebar restoration and resizing. Existing capture, placement, geometry, permission-consent, and effect tests pass.

Initial native walkthrough: idle, live, repeat selection, pause, resume, clear, Stage Only, Escape restoration, all six Settings panes, Settings Tab/Space isolation, effect activation without focus loss, compact layout at an 800-point window width, divider dragging, mode-change width restoration, keyboard source browsing, full-title previews, and presentation-guide sizing.

Follow-up preferences: Tools now stay open at every window size. The workspace has one settings gear, with no per-effect settings actions or window-layout menu. Source selection and keyboard focus outline only the outer tile. A transparent backdrop replaces the unstyled stage’s black fill; capture and video layers already preserve alpha.

Follow-up validation: all 123 tests pass and the development app builds and signs. The native walkthrough confirmed transparent App Store corners, a single outer live/paused outline, one working Settings gear, and all five tools visible in both tall and short workspaces. The layout menu is absent. The updated app is running with App Store on stage and effects off.

The Impeccable detector returned no findings, but it does not scan Swift; it is not evidence of a clean native audit.

Unverified conditions remain explicit: an actual remote meeting, VoiceOver speech and asynchronous announcements, light-mode and system accessibility-display variations, floating-widget runtime placement across displays, and frame-time/slow-motion profiling. No failure in those conditions was established by the original review, and this implementation does not claim certification of them.
